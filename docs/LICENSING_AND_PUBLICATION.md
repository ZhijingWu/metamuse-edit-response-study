## Sanitization and exclusions

- Publish prompts/generation parameters, model output text, extracted candidate programs, usage, failures, costs and evaluation records needed for verification.
- Omit full provider response envelopes, including request/response identifiers. Remove provider response-ID and credential-source metadata from structured exports. Scientific identifiers (parent, slot, candidate, attempt) remain intact.
- Exclude provider documentation downloads, original credential checks, parser-source backup copies, redundant snapshots and derived duplicate tables. Retain frozen protocols, current evaluator/selector code, all current call outcomes and superseded negative CPU results.
- Compress the large continuation replay JSON losslessly. No workload, score or failed call is replaced by a prediction.
- Keep the original development manifests as provenance identities, with a separate export map and public manifest. Sanitized files do not pretend to match original byte hashes.

The security check scans all staged text files and extracted PDF text for credential values/patterns, private paths, account identifiers and private/unrelated materials. It reports counts and file locations without printing matched secret values. Generic credential environment-variable names and the public API endpoint in historical acquisition code are not credentials. Actual credentials and authorization headers are not included. Public author contact links in the note are intentional.
